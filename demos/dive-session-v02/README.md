# KAWASEMI DIVE SESSION v0.2 — isolated prototype

Status: **OWNER_REVIEW_READY — isolated session-value prototype only**  
Production KAWASEMI integration: **not performed**.

This prototype tests the v0.2 experience hypothesis from `docs/DIVE_EXPERIENCE_V0_2.md`:

> Does DIVE become more worth returning to when the observable exploration session survives leaving, branching, orientation changes, and later resume?

The existing `demos/dive-focus-map/` remains preserved as technical interaction evidence. This prototype does **not** assume FOCUS MAP is the final DIVE UI.

GitHub Pages:

## 1–2 minute review path

1. In the CARDS-like article, scroll to any position.
2. Use the small top-bar `DIVE` action. The current article + exact reading position become the session anchor.
3. Choose `EVIDENCE` → `衛星画像`.
4. Move sideways to `HISTORY`.
5. Open the arrival `historically_similar_to` connection and confirm:
   - relation type is visible in text;
   - the sheet explicitly says historical similarity is **not evidence** for the current event;
   - source / provenance is inspectable.
6. `SAVE` that discovery explicitly.
7. Go BACK to Satellite imagery and branch to `TECHNOLOGY`.
8. Choose `問いをあとで確認`, review/edit the proposed wording, then explicitly `KEEP OPEN QUESTION`.
9. Open `SESSION` on Portrait (always visible in Landscape) and confirm both the HISTORY branch and TECHNOLOGY branch remain in Session History.
10. `LEAVE DIVE`.
11. On DIVE Home, verify `CONTINUE` comes before `RECENT DIVES` and only observable metadata is shown.
12. `CONTINUE`; the exact current focus, branches, saved discovery, open question, and anchor are restored.
13. Return to `CARDS`; the original article scroll position is restored.
14. Rotate / resize Portrait → Landscape → Portrait while exploring; the same session state remains.
15. Reload the deployed page, open DIVE Home, and use CONTINUE to manually verify real IndexedDB persistence on your browser. (Automated real-origin IndexedDB reload is listed under NOT TESTED below.)

## Interaction model used here

The visual interaction is intentionally simple: **current focus + a small editorial list of next semantic directions**.

It is not a new final DIVE visual concept. It exists only to make Session / Continue / Recent Dives / Resume easy to evaluate.

Directions are generated by a replaceable exploration adapter and display only fixture directions that actually have content. The root exposes seven directions in this fixture:

- EVIDENCE
- CLAIMS
- UNKNOWN
- HISTORY
- PEOPLE
- TECHNOLOGY
- IMPACT

Each direction includes a plain-language question.

## Replaceable Session architecture

The prototype deliberately separates session persistence from the interaction rendering so future DIVE LAB UIs can reuse the same session layer.

### `exploration-adapter.js`

`FixtureExplorationAdapter` exposes:

- `getNode(nodeId)`
- `getDirections(nodeId)`
- `getRelation(relationId)`
- `getSource(sourceId)`
- plain-language relation labels
- suggested-but-not-persisted Open Question wording

A future FOCUS MAP, lanes UI, newsroom UI, timeline UI, or another LAB interaction can replace this adapter / renderer without changing what a session means.

### `session-engine.js`

`DiveSessionEngine` owns UI-independent session behavior:

- create anchor session;
- first meaningful exploration persistence;
- current step;
- parent / branch traversal;
- trail derivation;
- move / back / jump;
- explicit Saved Discovery;
- explicit Open Question;
- pause / resume;
- approximate active exploration duration.

Branch history uses `parentStepId`; BACK does not delete earlier steps.

### `session-store.js`

Runtime persistence uses IndexedDB:

- DB: `kawasemi-dive-session-v02`
- object store: `sessions`

The persistent records contain the v0.2 concepts:

- `DiveSession`
- `DiveSessionStep`
- `SavedDiscovery`
- `DiveOpenQuestion`

The session is kept as an in-memory draft until the first meaningful exploration action. Accidental DIVE opens therefore do not pollute Recent Dives.

The browser automation harness defines a test-only storage backing through `window.__DIVE_TEST_PERSIST__`; deployed/runtime code uses IndexedDB when that test hook is absent.

## Session semantics

Automatically recorded observable state:

- anchor article;
- article origin scroll position;
- nodes actually opened;
- route / branch steps;
- typed relation used for each move;
- timestamps;
- approximate active exploration time;
- current / resume step.

Explicit-only state:

- Saved Discovery;
- Open Question.

Not recorded / inferred:

- understanding percentage;
- knowledge level;
- mastery;
- belief;
- political agreement;
- AI-inferred interest in a viewpoint.

`visited ≠ saved` is visible in the interaction and data model.

`UNKNOWN ≠ OPEN QUESTION`:

- `UNKNOWN` is an epistemic state of information.
- `OPEN QUESTION` is a user-controlled session item that exists only after explicit KEEP.

## DIVE Home contract exercised

Priority order:

1. `CONTINUE`
2. `RECENT DIVES`
3. `NEW EXPLORATION`

Recent rows show only observable metadata:

- anchor title;
- last focus;
- last active;
- approximate active exploration time;
- Saved Discovery count;
- Open Question count.

Two clearly labelled fixture sessions are seeded so multiple Recent Dives can be visually stress-tested. Resetting the demo recreates only those fixture sessions.

There is no DIVE completion percentage or required finish state.

## Information-integrity rules exercised

The fixture and UI maintain:

- attribution ≠ verification;
- historical similarity ≠ evidence;
- AI / processing confidence is not truth confidence;
- AI alone does not mark a proposition CONFIRMED;
- relation names are readable as text, not color-only;
- provenance remains inspectable;
- `historically_similar_to` is presented with an immediate warning that it is not supporting evidence.

No generic `related` relation is used.

### Visual bugs found and fixed during QA

1. The first article-level DIVE action was initially overlaid on article content at some scroll positions.
   - Root cause: absolute positioning inside the article frame.
   - Fix: moved the quick DIVE action into the topbar.

2. At 844×390, the Open Question confirmation initially fell below the visible sheet area.
   - Root cause: portrait-oriented sheet spacing and textarea minimum height.
   - Fix: short-Landscape sheet / textarea spacing override.

3. The `historically_similar_to` warning could appear lower than ideal in Portrait.
   - Root cause: warning followed explanatory paragraphs.
   - Fix: warning now appears immediately after the plain-language relation meaning.

Final known visual FAILs from the inspected matrix: **none**.

## Visual drift report

Preserved from production KAWASEMI:

- system / Helvetica Neue / Noto Sans JP stack;
- deep blue-black / charcoal surfaces;
- off-white text;
- restrained kingfisher teal;
- thin structural rules;
- restrained radius / depth;
- 62px-style topbar proportions;
- 65px-style bottom navigation proportions;
- content-first hierarchy;
- no neon / game / graph-database / generic SaaS styling.

Intentional differences:

- DIVE Home and Session History do not exist in production yet, so their layout is prototype-specific.
- Landscape exposes Session History persistently to test the value of wider investigative context.
- A visible topbar `DIVE` action exists only to test starting a session from an arbitrary reading position without modifying production CARDS gestures.

These differences are experience-test scaffolding, not production UI approval.

## Known limitations

- All news, provenance, and historical material is synthetic fixture content.
- The two pre-seeded Recent Dives are labelled demo sessions and exist to stress the session list.
- Active exploration time is approximate and intentionally not a productivity / knowledge score.
- There is no backend or cross-device state.
- There is no automatic “updated since your last DIVE” behavior.
- Saved Discovery is kept inside DIVE Session only; production global SAVED integration is deferred.
- Open Question resolution / new-evidence notification is not implemented.

## Production safety

This prototype is isolated under `demos/dive-session-v02/`.

It does not modify:

- production CARDS gesture code;
- production DIVE UI;
- production navigation;
- production backend;
- DIVE LAB workstreams;
- the existing `demos/dive-focus-map/` evidence prototype.

Before production integration, the Session model should be mapped to a server-side persistence contract and tested against real DIVE Node / Relation projections without changing the epistemic invariants above.
